# AI 对话 宪法
<!-- 本项目为 AI 对话 Web 前端应用（目录：ai对话） -->

## 核心原则

### 一、全站中文
整个网站所有面向用户的可见文本必须使用中文，包括：页面文案、按钮、菜单、提示信息、错误消息、加载状态、帮助文档、聊天消息渲染、日期与数字格式。除专有名词（品牌名、技术术语、代码标识符）外，不得以英文或其他语言作为界面默认语言。

理由：目标用户为中文用户，全站中文保证一致且无障碍的浏览体验。

### 二、禁用蓝紫色渐变 UI
界面设计禁止使用蓝紫色渐变（blue-purple gradient）作为任何视觉方案，包括但不限于：蓝紫渐变背景、渐变按钮、渐变卡片、渐变边框、渐变标题文字、渐变图标。配色必须采用简洁、低饱和、对比清晰的色板。

理由：蓝紫色渐变易造成视觉疲劳与廉价感，与本项目简洁、专业的视觉定位不符。

### 三、对话体验优先
作为 AI 对话网站，聊天交互必须优先保证易用性：消息流清晰可读、输入区始终可达、回复支持流式展示、历史会话可随时切换。任何功能改动不得破坏对话核心流程。

理由：对话是本站的第一功能，交互流畅度直接决定产品价值。

### 四、简洁视觉与无障碍
视觉风格必须简洁克制：不使用装饰性重渐变、炫彩动画或高饱和大面积色块。文本对比度、字号须满足基本可访问性要求。

理由：简洁克制的界面降低认知负担，适配更广泛的用户。

### 五、响应式适配
网站必须适配桌面端与移动端浏览器，核心对话功能在窄屏下保持完整可用，不出现横向滚动或元素重叠。

理由：用户在手机与电脑上都会使用对话功能，需保证跨设备体验一致。

## 设计规范

- 配色：以低饱和中性色为基础，辅以单一强调色；禁止蓝紫色渐变及大面积高饱和渐变。
- 字体：优先使用中文字体栈（含系统默认中文字体），保证中文渲染清晰。
- 文案：所有 UI 组件文案使用中文，同一术语在全站保持一致。
- 图标与配图：不得采用依赖渐变着色的主视觉风格。

## 开发流程

- 开发与评审时，所有面向用户的文案须通过「全站中文」校验。
- UI 设计稿与实现代码须通过「禁用蓝紫渐变」检查。
- 功能实现遵循 Spec Kit 流程：Specify → Plan → Implement → Checklist。

## 治理

本宪法约束项目的所有 UI、交互与开发工作。修改本宪法的提案必须：
1. 明确说明修改内容与理由；
2. 经项目负责人批准；
3. 更新版本号并记录修订日期。

版本号遵循语义化版本：主版本号用于治理原则的重大变更；次版本号用于新增原则或实质扩充；修订号用于措辞澄清等非语义优化。
